# Multiplayer Plan 3: Races Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** From free roam, any player can start a race on a built-in route. Others accept the invite, everyone lines up on a grid, counts down, drives through checkpoints with live positions and laps, and sees the same results. Then everyone goes back to free roam.

**Architecture:** Race rules (routes, checkpoint order, laps, standings, finish order, timeouts) live engine-free in `mp/common`, so they're unit tested. The host runs the authoritative `CRaceState`. Each racer detects its own checkpoint crossings and stamps them with session time. The host orders results by those timestamps, which is the spec's builder call. The in-game side (`src/multiplayer/NetRace`) handles invites, grid, countdown, markers, HUD and respawn.

**Tech Stack:** Plans 1–2 (`mpcommon`, `CNetGame`, `CNetVehicles`, `CFreeroamMenu`, `CNetChat`), reVC engine.

**Spec:** `docs/superpowers/specs/2026-10-31-multiplayer-design.md` (Goals §4). Depends on Plans 1 and 2 being complete.

## Global Constraints

- One race at a time per session. Players not racing keep playing free roam and see racers as normal players.
- Any player in free roam can start a race. Invites are open for **15 s**.
- **3-2-1-GO countdown**, with racers frozen on the grid until GO.
- Checkpoints use the game's standard markers (`C3dMarkers` cylinders) + radar blips, and the **next checkpoint is previewed**.
- **Live position (1st/2nd/…), lap counter for circuits, race timer.**
- **The finish screen** shows order and times; then everyone returns to free roam.
- **Wrecked or stuck cars respawn at the last checkpoint.**
- **At least 4 routes** (a mix of sprint and circuit, land-only), as data files loadable without recompiling.
- **Results are identical on every screen**, and a close finish matches what each racer saw (order by crossing timestamps on the shared session clock).
- Single-player untouched: `#ifdef MULTIPLAYER` + `CNetGame::IsActive()` everywhere in `src/`.
- `mp/common` stays engine-free C++11.

## Review Focus

1. **A racer disconnects, crashes or leaves mid-race.** They're marked DNF; the race still ends for everyone with consistent results. Tested in Task 2 (`OnLeft`).
2. **Checkpoints out of order** (cutting a corner, skipping a checkpoint, or a duplicate message after a resend). Only the expected next checkpoint counts; others are ignored without penalty. Tested in Task 2.
3. **A photo finish.** Two finish times are 3 ms apart, and the packet from the later finisher arrives at the host first. The earlier timestamp still wins; an exact tie goes to the lower player id. Tested in Task 2.
4. **Dying, wrecking or flipping mid-race.** The racer respawns at the last checkpoint in a fresh race car, keeps their progress, and the timer keeps running. Owned by Task 4, in-game check.
5. **A bad route file** (missing fields, fewer than 2 checkpoints, a circuit with 0 laps, garbage numbers). It's skipped with a logged reason; the game and the race menu still work. Tested in Task 1.

### Task 1: Route format and parser

**Files:**
- Create: `mp/common/RaceRoute.h/.cpp`, `mp/tests/test_raceroute.cpp`

**Interfaces:**
- Produces:
  - `MP_MAX_CHECKPOINTS = 64`.
  - `enum eRaceType { RACE_SPRINT, RACE_CIRCUIT }`.
  - `struct SRaceGridSlot { float pos[3]; float heading; }` (`heading` in degrees, as authored).
  - `struct SRaceCheckpoint { float pos[3]; float radius; }`.
  - `struct SRaceRoute { char name[32]; uint8_t type; uint8_t laps; uint16_t vehicleModel; uint8_t numGrid; SRaceGridSlot grid[MP_MAX_PLAYERS]; uint8_t numCheckpoints; SRaceCheckpoint cps[MP_MAX_CHECKPOINTS]; }`.
  - `bool MpParseRoute(const char *text, SRaceRoute &out, char *err, uint32_t errSize)`.
  - `uint16_t MpRouteTotalCrossings(const SRaceRoute&)`: sprint gives `numCheckpoints`; circuit gives `numCheckpoints * laps`.
- File format (`.route`, UTF-8 text, `#` comments, one directive per line, whitespace-separated):
  ```
  name Ocean Drive Sprint
  type sprint            # or circuit
  laps 1                 # required for circuit (1..9); sprint forces 1
  vehicle 132
  grid  X Y Z HEADING    # 1..8 lines, slot order = grid order
  cp    X Y Z RADIUS     # 2..64 lines, in driving order; last cp = finish line (circuit: also lap line)
  ```
- Validation errors (exact `err` prefixes, so tests can match): `"missing name"`, `"bad type"`, `"bad laps"`, `"bad vehicle"`, `"no grid"`, `"too few checkpoints"`, `"too many checkpoints"`, `"line N: bad number"`.

- [ ] **Step 1: Write failing tests:**
  - A valid sprint (2 grid, 3 cps) parses all fields; `MpRouteTotalCrossings == 3`.
  - A valid circuit with `laps 3` and 4 cps gives 12.
  - Comments and blank lines are ignored.
  - Each validation error above is triggered by a minimal bad file and its `err` starts with the expected prefix.
  - 9 grid lines keep the first 8 and parse OK.
  - A sprint with `laps 5` still gets `laps == 1`.
- [ ] **Step 2: Run, expect fail** (no `RaceRoute.h`).
- [ ] **Step 3: Implement** with `strtod`/`strtol`, checking the end pointer (no exceptions, no iostreams).

### Task 2: Race rules (`CRaceState`)

**Files:**
- Create: `mp/common/RaceLogic.h/.cpp`, `mp/tests/test_racelogic.cpp`

**Interfaces:**
- Consumes: `SRaceRoute`, `MpRouteTotalCrossings`.
- Produces `struct SRacer { uint8_t id; uint16_t nextSeq; uint32_t lastCrossTime; uint32_t finishTime; float distToNext; uint8_t state; }` with `enum { RACER_RACING, RACER_FINISHED, RACER_DNF }`.
- Produces `class CRaceState`:
  - `void Start(const SRaceRoute &route, const uint8_t *ids, int numRacers, uint32_t startTime)`.
  - `bool OnCrossing(uint8_t id, uint16_t seq, uint32_t time)`: accepts only `seq == nextSeq` with `time >= startTime`; the last seq makes the racer FINISHED with `finishTime = time - startTime`.
  - `void SetDistance(uint8_t id, float d)`.
  - `void OnLeft(uint8_t id)`: makes the racer DNF.
  - `void Update(uint32_t now)`.
  - `int GetStandings(uint8_t outIds[MP_MAX_PLAYERS]) const`.
  - `bool IsOver() const`, `const SRacer *GetRacer(uint8_t id) const`, `int NumRacers() const`.
  - `uint8_t LapOf(uint8_t id) const`: 1-based current lap for circuits.
- Rules (exact):
  - **Standings order:** FINISHED by `finishTime` ascending (tie → lower id); then RACING by `nextSeq` descending, then `distToNext` ascending (tie → lower id); then DNF (by id).
  - **End:** the race is over when no racer is RACING, **or** 60 000 ms after the first finish (remaining racers become DNF), **or** 20 min after start (everyone still racing becomes DNF).

- [ ] **Step 1: Write failing tests** with a 3-cp sprint and 3 racers (ids 0, 1, 2), start at t=10 000:
  - `in order`: crossings 0, 1, 2 by id 1 → FINISHED, `finishTime == lastTime − 10000`.
  - `skip rejected`: id 0 sends seq 1 before 0 → false; nextSeq stays 0.
  - `duplicate rejected`: seq 0 twice → the second returns false.
  - `before start rejected`: seq 0 at t=9 999 → false.
  - `photo finish`: id 2 finishes at 50 003; id 1's finish arrives later in call order but has time 50 000 → standings `[1, 2, ...]`.
  - `exact tie`: both at 50 000 → lower id first.
  - `racing order`: id 0 at nextSeq 2 dist 50, id 2 at nextSeq 2 dist 10 → `[2, 0]`.
  - `dnf on leave`: `OnLeft(0)`; when the others finish, `IsOver()` and id 0 is last.
  - `timeout after first finish`: id 1 finishes at 40 000; `Update(100 001)` → others DNF, `IsOver()`.
  - `circuit laps`: 2 cps × 3 laps; `LapOf` goes 1→2 after seq 1 (the lap line), and finishing needs seq 5.
- [ ] **Step 2: Run, expect fail.**
- [ ] **Step 3: Implement.**
- [ ] **Step 4: Run, expect pass.**
- [ ] **Step 5: Commit.** `git commit -m "mp: host-side race rules with timestamp-ordered results"`

### Task 3: Race messages + fake-client race bot

**Files:**
- Modify: `mp/common/GameProtocol.h/.cpp`, `mp/tests/test_gameprotocol.cpp`, `mp/tools/fakeclient.cpp`

**Interfaces:**
- Produces messages (`raceId` is a `u16` the host increments per race; messages with a stale `raceId` are ignored):
  - `GMSG_RACE_REQUEST = 80` (→ host, reliable): `char route[32]`. The host rejects if a race is already pending or running (reply `GMSG_RACE_CANCEL` to the requester with reason `RACE_BUSY`).
  - `GMSG_RACE_INVITE = 81` (host → all): `u16 raceId; u8 startedBy; char route[32]; u32 deadline` (session time, now + 15 000).
  - `GMSG_RACE_ACCEPT = 82` (→ host): `u16 raceId`. The starter is auto-accepted. Accepts after the deadline are ignored.
  - `GMSG_RACE_START = 83` (host → all): `u16 raceId; u32 startTime` (session time = deadline + 5 000; the countdown shows during the last 3 000 ms); `u8 n; u8 ids[n]` (index = grid slot).
  - `GMSG_RACE_CROSS = 84` (racer → host, reliable): `u16 raceId; u16 seq; u32 time`.
  - `GMSG_RACE_STANDINGS = 85` (host → all, 4 Hz, unreliable): `u16 raceId; u8 n; {u8 id; u16 nextSeq; u8 state; u32 finishTime}[n]` in standings order.
  - `GMSG_RACE_END = 86` (host → all, reliable): the same body as STANDINGS (final).
  - `GMSG_RACE_CANCEL = 87` (host → all/one): `u16 raceId; u8 reason` (`RACE_BUSY`, `RACE_NO_RACERS` (fewer than 1 accepted), `RACE_BAD_ROUTE` (the host lacks that route file)).
- The host computes `distToNext` from the `GMSG_PLAYER_STATE` positions it already receives, so racers don't send distance separately.
- Fake client `--bot race`: auto-accepts any invite. After `RACE_START`, it sends `RACE_CROSS` seq 0..N−1 every 4 s of session time, printing STANDINGS/END. That lets a single real player test a full race with bots.

- [ ] **Step 1: Write failing tests:** a round trip for each race message, and STANDINGS with 8 entries ≤ 100 bytes.
- [ ] **Step 2: Run, expect fail. Step 3: Implement. Step 4: Run, expect pass.**
- [ ] **Step 5: Manual check without the game.** `relay` + `fakeclient --host` (a temporary `--start-race NAME` flag on the fake host that runs `CRaceState` like the game host will; reuse the `CRaceState` class, no duplication) + 2× `fakeclient --join CODE --bot race`. The host prints standings and a final END listing both bots.

### Task 4: In-game race flow

**Files:**
- Create: `src/multiplayer/NetRace.h/.cpp`
- Modify: `src/multiplayer/NetGame.cpp` (dispatch 80..87, call `CNetRace::Process/Render`, `CNetRace::OnPlayerLeft`), `src/multiplayer/FreeroamMenu.cpp` (via `AddItem`: "Start race ▸" listing loaded routes), `src/multiplayer/MpText.cpp`

**Interfaces:**
- Consumes: `CRaceState`, `MpParseRoute`, race messages, `CNetVehicles::Register`, `CSpawnPoints`, `CNetChat::AddLine`, `CFreeroamMenu::AddItem`, `CNetGame::Client().SessionTime(now)`.
- Produces `class CNetRace` (static):
  - `void Init()`: loads every `data/mp/races/*.route` via `CFileMgr`; bad files are logged with `debug(...)` and skipped.
  - `void Process()`, `void Render()`, `bool IsRacing()`, `void OnMessage(uint8 from, uint8 type, CByteReader&)`, `void OnPlayerLeft(uint8 id)`, `void Reset()`.
  - Host only: owns `CRaceState`, handles REQUEST/ACCEPT/CROSS, sends INVITE/START/STANDINGS/END/CANCEL.
- **Flow (exact):**
  1. **Invite:** the chat line "Tommy started *Ocean Drive Sprint* — press F3 to join (15s)" and a countdown in the HUD corner. `F3` sends ACCEPT.
  2. **On START (racers only):**
     - Exit any vehicle (passengers too).
     - Spawn the route's `vehicleModel` at `grid[slot]` and warp into it as driver.
     - Freeze it (`bIsFrozen = true; bInfiniteMass = true`, as in `FREEZE_CAR_POSITION`) and `SetDisablePlayerControls(PLAYERCONTROL_CUTSCENE)`.
     - Close the free-roam menu.
  3. **Countdown:** big centred `3`, `2`, `1`, `GO!` from `CFont` at `startTime − 3000/2000/1000/0` session time, plus the frontend beep. At GO, unfreeze and enable controls.
  4. **Checkpoints:**
     - Each frame, `C3dMarkers::PlaceMarker` a yellow cylinder at the current cp (radius × 2 for visual size) and a smaller translucent one at the next.
     - Radar: `CRadar::SetCoordBlip` for current (yellow) and next (dimmer, smaller); replace them on advance.
     - The finish cp is a red/white marker (`MARKERTYPE_CYLINDER`, red).
     - A crossing happens when the player's vehicle position is within `radius` in XY and within 6 m in Z. Send `RACE_CROSS{seq, SessionTime(now)}` and advance locally right away (optimistic); the host's STANDINGS are the truth for position.
  5. **HUD** (`CFont` in `Render`, top-right): `POS 2/4`, `LAP 2/3` (circuit only), `TIME 01:23.45` (now − startTime), and the next checkpoint `7/12`.
  6. **Respawn at last checkpoint:**
     - Trigger it when the car is wrecked (`m_fHealth < 250` or blown up), the player is out of the car for 5 s, the player dies, or `H` is held for 1.5 s (stuck/flipped).
     - Respawn in a fresh race car at the last crossed cp (grid slot if none), heading toward the next cp, with a 1 s freeze.
     - If the player died, the Plan 2 respawn is overridden to this position (`CRestart::OverrideNextRestart`).
  7. **Finish:** on END, show the results panel for 10 s (place, name, time `mm:ss.hh` or `DNF`), then unfreeze, clear markers and blips, keep the player in their car where they are, and return to free roam.
  8. **Non-racers** see invite/finish chat lines only ("Lance won *Ocean Drive Sprint* in 01:42.10").
  9. **Host-side:** STANDINGS at 4 Hz; `CRaceState::Update` each frame; when `IsOver()`, send END.

- [ ] **Step 2: Build on Linux + CI green on all 3 OSes.**

### Task 5: Route recorder and the 4 built-in routes

**Files:**
- Create: `src/multiplayer/RouteRecorder.h/.cpp`, `gamefiles/data/mp/races/*.route` (4 files)
- Modify: `src/multiplayer/NetChat.cpp` (chat lines starting with `/` are local commands, never sent)

**Interfaces:**
- Produces chat commands (available in any session; they're harmless, since they only write local files):
  - `/rec new NAME` and `/rec type sprint|circuit`, `/rec laps N`.
  - `/rec vehicle`: uses the current vehicle's model.
  - `/rec grid`: adds the current position + heading as the next grid slot.
  - `/rec cp [radius]`: adds the current position, default radius 8.
  - `/rec undo`: removes the last line added.
  - `/rec save`: writes `data/mp/races/<name-slug>.route` in the format from Task 1, then reloads routes via `CNetRace::Init()`.
  - `/pos` prints the current coordinates to chat.
- The 4 routes (needs the game installed; land-only, using roads Vice City players know):
  1. **Ocean Drive Sprint**: sprint along Ocean Beach's Ocean Drive, north to south.
  2. **Starfish Loop**: circuit, 3 laps, around Starfish Island.
  3. **Bridge Run**: sprint from Ocean Beach across a bridge to Downtown.
  4. **Little Havana Circuit**: circuit, 2 laps, through Little Havana / Little Haiti streets.
  - Each has 8 grid slots spaced 4 m laterally × 8 m back, 8–20 checkpoints, and a sports car (model chosen in-game).
